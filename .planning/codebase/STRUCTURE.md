## Directory Purposes

**backend/:**
- Purpose: RESTful API server written in Go
- Contains: HTTP handlers, business logic, database operations
- Key files: `main.go` (entry point), `handlers/handlers.go` (endpoints), `services/services.go` (logic), `repository/repository.go` (database)

**frontend/:**
- Purpose: React single-page application (SPA)
- Contains: React components, styling, build configuration
- Key files: `src/App.jsx` (root component), `src/components/` (pages and features)

**docker-compose.yml:**
- Purpose: Defines containerized environment for local development
- Contains: 4 services — frontend (Vite dev server), backend (Go API), database (PostgreSQL), pgadmin (database GUI)

**.planning/codebase/:**
- Purpose: Architecture and structure documentation
- Contains: ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, TESTING.md, CONCERNS.md (as analysis progresses)

## Key File Locations

**Entry Points:**
- `backend/main.go`: Go server initialization, database connection, router setup
- `frontend/src/main.jsx`: React DOM root mount
- `frontend/src/App.jsx`: React routing and theme management

**Authentication:**
- `backend/handlers/handlers.go`: LoginUser, CreateUser, GetUser endpoints
- `backend/services/services.go`: CreateSession, LoginUser, GetUserBySession logic
- `frontend/src/components/Login.jsx`: Login form
- `frontend/src/components/Signup.jsx`: Registration form

**Configuration:**
- `backend/.env`: Database connection variables (DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME)
- `frontend/vite.config.js`: Vite build and dev server config
- `docker-compose.yml`: Development environment setup
- `frontend/src/index.css`: Tailwind CSS theme variables

**Core Logic:**
- `backend/services/services.go`: User creation, login, session management
- `backend/repository/repository.go`: All database queries
- `frontend/src/components/Navbar.jsx`: User state and profile display

**Styling:**
- `frontend/src/index.css`: Tailwind CSS imports and custom CSS variables (dark/light theme)
- `frontend/src/App.css`: App-level styles
- Components use Tailwind utility classes (e.g., `bg-ui-light-bg`, `text-ui-text`)

## Naming Conventions

**Backend Files:**
- Pattern: `lowercase.go` with package-scoped functions
- Example: `handlers.go`, `repository.go`, `services.go`, `models.go`, `util.go`

**Backend Functions:**
- Pattern: PascalCase for exported (public) functions, camelCase for unexported (private)
- Example: `NewHandlerLayer()`, `LoginUser()`, `connectToDatabase()`

**Backend Structs:**
- Pattern: PascalCase for types, PascalCase for exported fields
- Example: `HandlerLayerInstance`, `RepositoryLayerInstance`, `User`

**Frontend Files:**
- Pattern: PascalCase for components (e.g., `Login.jsx`, `Signup.jsx`, `Navbar.jsx`)
- Pattern: lowercase for utilities and hooks (e.g., `main.jsx`, `index.css`)

**Frontend Components:**
- Pattern: Default export, named same as file
- Example: `export default function Login() { ... }` in `Login.jsx`

**Frontend Variables:**
- Pattern: camelCase for functions and variables
- Example: `handleSubmit()`, `setUser()`, `handleChange()`

**CSS Class Names:**
- Pattern: Tailwind utilities + custom prefixed classes
- Example: `bg-ui-light-bg`, `text-ui-text`, `bg-ui-btn`, `text-ui-btn-text`
- Theme colors defined in `index.css` with CSS custom properties

## Where to Add New Code

**New Authentication Feature:**
- Backend endpoint: `backend/handlers/handlers.go` → add handler function
- Business logic: `backend/services/services.go` → add service method
- Database: `backend/repository/repository.go` → add query method
- Frontend form: `frontend/src/components/` → create new component
- Route: Update `frontend/src/App.jsx` with new Route

**New User Profile Feature:**
- Start in: `frontend/src/components/ProfilePage.jsx` (currently minimal)
- Add endpoint to backend: `backend/handlers/handlers.go`
- Add service method: `backend/services/services.go`
- Add repository method: `backend/repository/repository.go`
- Connect fetch in component to call `/me` or new endpoint

**New Dashboard/List Feature:**
- Create component: `frontend/src/components/Dashboard.jsx` (new file)
- Add route: `frontend/src/App.jsx` → `<Route path="/dashboard" element={<Dashboard />} />`
- Create backend endpoint: `backend/handlers/handlers.go`
- Add service and repository methods as needed

**Styling New Component:**
- Use existing Tailwind classes: `bg-ui-bg`, `bg-ui-light-bg`, `text-ui-text`, `bg-ui-btn`
- Reference theme colors in `frontend/src/index.css`
- Follow dark/light theme pattern (CSS custom properties with [data-theme] selector)

**Database Changes:**
- Add migration SQL: `backend/migrations/` (currently unused; SQL files can be placed here)
- Update schema: Modify backend table definitions (currently stored in database-data volume)
- Update models: `backend/models/models.go` → add new struct fields
- Update repository: `backend/repository/repository.go` → update SELECT/INSERT statements

## Special Directories

**database-data/:**
- Purpose: PostgreSQL data persistence
- Generated: Yes (created by PostgreSQL container)
- Committed: No (in .gitignore; only structure exists in repo)

**dist/:**
- Purpose: Built frontend production artifacts
- Generated: Yes (by `npm run build`)
- Committed: No (in .gitignore; generated at build time)

**node_modules/:**
- Purpose: Frontend npm dependencies
- Generated: Yes (by `npm install`)
- Committed: No (in .gitignore; use package-lock.json)

**.claude/:**
- Purpose: Claude Code configuration (hooks, settings)
- Generated: No (created by user)
- Committed: Yes (project-specific Claude configuration)

**.git/:**
- Purpose: Git version control metadata
- Generated: Yes (by git init)
- Committed: N/A (git internal directory)
